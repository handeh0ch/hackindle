# KOReader capture boundary

`plugin/main.lua` follows KOReader's [WidgetContainer plugin pattern](https://github.com/koreader/koreader/blob/master/plugins/hello.koplugin/main.lua) and observes reader events. The later configuration/transport layer must call its configuration boundary with an authenticated profile and the required native adapters; without them, capture remains unavailable. The shipped code is not yet a complete installable plugin.

The entrypoint only forwards a source, annotation set, lifecycle observation or reading sample when its adapter supplies the required evidence. A page token must describe durable native observation state; a full rerender must invalidate the new-layout token before it can be credited. Current upstream KOReader emits `PageUpdate` before `DocumentRerendered` during full rerendering, as described in [readerrolling.lua](https://github.com/koreader/koreader/blob/master/frontend/apps/reader/modules/readerrolling.lua) and the [statistics plugin](https://github.com/koreader/koreader/blob/master/plugins/statistics.koplugin/main.lua). These are upstream references, not observations of the owner's installed version. Failed page finalization retains the token in memory and blocks a subsequent source until reconciliation; the adapter must retain its durable evidence across plugin restart.

`koreader_metadata.lua` maps documented `ui.doc_props` fields but requires an injected, verified exact-file identity/format resolver and UTC clock. It does not implement reading, annotations or vocabulary. `koreader_runtime.lua` opens the private state adapter, retains a device UUID, and schedules incremental hashing through KOReader's next-tick callback; its caller must supply authenticated profile verification, a timezone provider and verified document-format detection. `koreader_hash.begin_file` performs two incremental SHA-256 passes with matching file attributes and never reads more than the requested bounded chunk per step. The caller must revalidate if the source changes. Two matching passes and filesystem attributes are not an OS lock and do not prove behavior on every filesystem. `koreader_entropy.uuid` uses nonblocking Linux `getrandom`; missing support or unavailable initialized entropy returns an explicit unavailable result, never a weaker fallback. Its symbol and availability on the installed Kindle remain unverified.

`koreader_annotations.lua` projects complete rolling-text highlight sets only when a separate adapter supplies verified durable native associations. Unsupported bookmarks, PDF geometry or ambiguous/missing associations leave the entire snapshot unavailable. Rolling-text context uses upstream CRE page and XPointer calls as backfill, only when no known selection is active and the reader position remains unchanged. The final rendered page and its preceding-page context work only if CRE returns a distinct ordered XPointer for page count plus one; upstream does not establish that endpoint, so missing or clamped boundaries remain pending. CRE explicitly clears selections when extracting text; completeness of the selection guard and installed-device behavior remain unverified. `koreader_statistics.lua` reads approximate historical records using KOReader's `page_stat_data` layout; it requires an independently verified binding from the exact SHA-256 source to the native book row. KOReader's native partial MD5 and title are not sufficient proof. Its native connection uses the documented LJSQLite3 `ro` mode when opened by this code. Neither native association is yet implemented or verified on the device. `koreader_vocabulary.lua` reads the upstream Vocabulary Builder `vocabulary.word` column in read-only mode, with unavailable language and dictionary source represented as null; suspend/close triggers a snapshot. Reset generations first capture a complete local baseline and wait for authenticated baseline acknowledgement before filtered snapshots; identical vocabulary re-saves still need a reliable native save signal. The upstream new-highlight event supplies an observed annotation creation signal, assigned a generated event UUID; event delivery uniqueness and timing remain unverified on the installed device. The installed schema, SQLite and WAL behavior are unverified.

`koreader_reading.lua` captures rolling-text visible page ranges using durable tentative tokens and UTC observation time; no native reading seconds are invented. It assumes one-based CRE internal page boundaries, comparator sign and selection signals; PDF and device proof remain unavailable; final-page extraction depends on the same unverified end-boundary behavior. A crash or close with an unresolved tentative token records a durable gap instead of claiming the page. A process-local exclusive provider prevents another live provider in that Lua process from recovering its token; this is not a cross-process lock. Hash/ACK-time gaps are counted durably but their intervals cannot be reconstructed. Legacy reset captures a complete read through the statistics adapter and establishes a generation-bound server baseline when an independently verified exact-source binding and continuous native epoch are available; it stays unavailable otherwise. Reset processing still depends on a complete native baseline and native save/interval evidence with durable identities. KOReader annotations do not expose a built-in durable identifier in the upstream structure. The device can observe a save after it has learned the new generation, but an offline device cannot classify an event between the server reset and its notification without additional reliable chronology. It must not invent that classification. Authenticated acknowledgement delivery, device configuration and native callback implementations remain unfinished; owner-run hardware observations are separate from the synthetic unit tests.
