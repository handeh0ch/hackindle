# API v1 contract

This is the shared implementation contract, not evidence of working device adapters. `contracts/*.schema.json` use JSON Schema draft 2020-12. `validate.js` uses Ajv and adds cross-field checks; `validateEnvelope` is required in addition to the envelope schema. Times ending in `Z` are UTC. Reporting dates use the initialized IANA timezone and do not depend on the host timezone. `measurement_version`, native record identity, extraction and timing provenance are provisional until P0 observations; they are not device-tested.

## Authentication and profile

All owner routes below require an owner cookie session. Device bearer credentials may access only sync, config, uploads and source cover upload, never owner reads or mutations. `POST /api/v1/auth/login` requires an allowed Origin and `application/json` body matching `login_action`. Success returns HTTP 200 with the `session` response (`owner.username`, `csrf_token`, `expires_at`) and a private opaque `kindle_sync_session` cookie: HttpOnly, SameSite=Lax, Secure under HTTPS, with a 14-day TTL. `GET /api/v1/auth/session` returns the same `session` shape for a valid cookie or 401; both session responses use `Cache-Control: no-store`. `POST /api/v1/auth/logout` requires an allowed Origin and `X-CSRF-Token` matching the session and returns 204 without JSON. Other owner mutations require the same Origin and CSRF checks and JSON requests; the raw cover upload is a device route. Invalid or missing authentication is 401; an authenticated but unauthorized principal is 403. Errors use `error` schema and include a stable code without credentials or submitted content.

`GET /api/v1/sync/config` returns `config`: instance UUID, protocol version 1, current reset generation, immutable reporting timezone and conditional-page denominator, plus exact byte/TTL limits. A mismatched saved instance or policy pauses the device until explicitly resolved; it must not silently replay data to a different instance or reproject prior history. All packets, manifests and acknowledgements carry the instance-scoped generation.

The panel obtains the same nonsecret `config` shape through cookie-authenticated `GET /api/v1/owner/config`, with `Cache-Control: private, no-store`. It does not need or store a device token to learn the reporting policy. This owner route uses the `config` definition in `sync.schema.json`; device bearer credentials cannot access it.

## Sync

Pre-release timestamp checkpoint: service UTC instants use four-digit years 0001–9999, seconds 00–59 and optional fractional seconds with one to nine digits. Leap-second `:60` values and greater precision are rejected; raw native annotation timestamp strings are not service instants and remain opaque. Reporting dates use years 0001–9999. Profile-dependent accounting rejects instants whose local reporting date falls outside that range. A reading segment allocates native credit across at most 366 distinct local dates; the device splits longer observations into separate immutable segments. This bound does not limit lifetime history. Preserve exact accepted fractions for weighting and ordering; avoid database timestamp rounding across a reporting-day boundary.

`POST /api/v1/sync` accepts an `envelope`; source SHA-256 is lowercase hex, seq is a monotonically increasing positive safe integer per device, and event IDs are stable UUIDs. `source_snapshot` contains independent optional `metadata`, `annotations`, and `progress` sections, each with its own positive `version` and `value`. At least one section is required. Successful complete `annotations.value: []` archives missing active annotations for that source; omission or unavailable extraction leaves the prior section unchanged. Reappearance of an existing ID reactivates it. Archive retains quote, note and context. The source's absence, native statistics clearing, incomplete upload, or failed extraction must not delete service history.

`reading_events` supplies immutable source-specific events. `vocabulary_snapshot` is a complete successfully read set and uses null source; unavailable vocabulary is omitted rather than sent as an empty set. `legacy_statistics` holds approximate native records separately from character-based totals. Vocabulary version identity is `(instance_id, reset_generation, device_id, vocabulary)`; a greater version replaces the successful complete set, an older version is stale, an equal version with the same canonical section digest is duplicate, and an equal version with changed content is 409. Legacy version identity is `(instance_id, reset_generation, device_id, source_id, legacy)` and follows the same version and digest gate. For a newer legacy snapshot, merge each supplied reporting date by componentwise maximum of `native_pages` and `native_seconds`; retain absent dates. Duplicate dates in one legacy packet are invalid. This approximate high-water archive is never added to new character or active-time series. Clearing native statistics does not clear the archive. Within each envelope, locator types must be homogeneous. B2 checks the locator engine against stored source format; the server cannot prove XPointer ordering or PDF geometry without the document. Source-specific ranges use native XPointers for rolling documents or original PDF page and geometry; these are not EPUB CFI. PDF geometry uses the adapter-native coordinate space identified by `geometry_version`; units, origin and transformation are provisional until P0. Page-only positions and bookmarks carry empty boxes and null geometry version. PDF highlights and measured ranges require actual geometry; never fabricate a full-page region. Metadata identifiers are matching evidence, not proof of edition equivalence.

Each segment credits volume on its explicit `volume_date` only, even when its native time allocation spans multiple days. A reading segment retains exact native seconds, native record identity, provenance, explicit timing quality, and newly credited characters with source-specific range evidence. `ranges` contains disjoint newly credited pieces, each with its exact Unicode character count under the versioned extraction rule; their counts sum to `credited_characters`. A zero-volume reread has an empty ranges array. The adapter establishes disjointness and ordering; the server must not compare opaque XPointers lexicographically. `unavailable` uses null amounts, not zero; native record ID and provenance can be null when no native record exists. A measured zero is valid for a reread. Observed UTC awake windows must be sorted and disjoint. Split their durations at local midnight in the initialized IANA reporting timezone, including DST transitions. For each date let its duration be `w_d`, total duration `W`, and native integer seconds `C`. Allocate `floor(C*w_d/W)`, then distribute remaining seconds by largest fractional remainder, breaking ties by earliest ISO date. Allocation dates are unique and ascending, and the sum equals `C`; freeze the result with the event. The pure contract validator and B2 ingestion check structural evidence: window ordering, disjointness, dates and the sum. B3 adds profile-dependent allocation recomputation at ingestion against the initialized reporting policy before release; P1 mirrors that calculation on the device. B2 alone does not establish accounting correctness. Window endpoints are chronology observations, not a new timer. If windows are unavailable, use `estimated_native_anchor`: allocate all native seconds to the anchor instant's local date in the initialized reporting timezone, with one allocation entry even for a measured zero. Do not fabricate an exact end; retain the resulting allocation permanently. Qualification, whitespace rules, native credit reconciliation and PDF geometry remain provisional until P0.

Annotation UUIDs are unique across the instance and permanently owned by their source. The plugin assigns a separate service UUID for a copied native annotation in another file; a cross-source UUID collision is 409 and cannot move the original note or context. Owner annotation/content routes use that unambiguous UUID.

Ready context includes all selected pages and one adjacent page where present. Missing neighbours are null only at the first/last page; an extracted blank page is an empty string. Pending/unavailable context retains the annotation and a reason. Origin is creation or backfill; backfill does not claim original layout. Bookmarks have null context. Edits to a note preserve context; selection changes recapture it.

The server validates before writes, applies an envelope atomically, and acknowledges only after commit. Deduplicate by `(device_id, seq)` and canonical semantic JSON SHA-256: recursively sort object keys by JavaScript UTF-16 code-unit order, preserve array order, use JSON serialization of primitives and no insignificant whitespace, then UTF-8 encode and hash. `canonicalDigest` accepts validated JSON values only; validate the packet before hashing or writing it. Identical retries are safe; different content under the same key returns 409. Immutable `event_id` has the same duplicate/conflict rule independently. Snapshot section ordering uses `(device_id, source_id, section, version)` independently: newer applies, equal identical duplicates, older is stale. Packet and event identities survive restarts and concurrency.

The `ack` repeats envelope schema version, instance, device, source, generation, seq and kind and includes `current_reset_generation`, status and exactly one result per supplied snapshot section; events use each event UUID as a result key; vocabulary and legacy use their kind as the sole result key. Normal immutable event results are `applied` or `duplicate`; a changed existing event is 409, and `stale` cannot acknowledge an event. Snapshot section, vocabulary and legacy results may also be `stale`. Obsolete-generation results are `discarded`. The client deletes a queue record only after `matchesAck` succeeds, including all identity and result keys. A malformed 200 is not an acknowledgement. Different content at an existing identity is 409, with no partial writes.

Vocabulary lists and counts identify a saved word by its word and language after JavaScript Unicode default lowercasing. Null language is distinct from any string; whitespace and Unicode normalization forms are preserved. Source metadata does not affect uniqueness. Snapshot version digests still cover the complete supplied content, including source metadata.

The authenticated sync profile advertises the `unicode_version` of the server's frozen casing tables (`server/unicode-casing.json`, generated together with the device table by `scripts/generate-unicode-casing.js`). The version does not depend on the Node.js runtime or its ICU, so a runtime upgrade never changes vocabulary identities. A device may process a vocabulary reset only when that version matches its bundled casing data. New post-reset vocabulary snapshots carry the same `unicode_version`; the server rejects a mismatch before applying them. The server retains the version used for vocabulary identity barriers in its backup-preserved reset tombstones and pauses new vocabulary writes if the frozen tables change or historical barriers have unknown casing provenance. Changing the casing data therefore needs a deliberate data migration, not a runtime upgrade. This also protects a queued packet if the tables change after the profile was fetched. Devices with missing or mismatched casing data leave vocabulary reset pending; other data is unaffected. Existing packet retries and obsolete-generation discards retain their prior handling.

## Reset barrier

`POST /api/v1/owner/reset` accepts `reset_action` and atomically increments the durable instance-wide `reset_generation`, clears service data, and retains generation and identity/tombstone barriers. Old-generation packets receive an `obsolete_discarded` ack: it repeats the packet generation, reports the newer `current_reset_generation`, and marks every expected result `discarded`. They never modify data. A future-generation packet is 409. Old queued content is removed only on a matching discard acknowledgement.

On observing a new generation the client pauses publication, transactionally captures and durably retains a local baseline for each native dataset and source before issuing new-generation captures for it. An unavailable source remains baseline-pending until accessible. The client suppresses unchanged pre-reset native objects during rescans; it never relabels old queued bytes or seq with the new generation. Matching obsolete acknowledgements are the only authority to discard that queue. Reset UI warns that old offline observations will be discarded and shows pending status. A server cannot determine the age of offline objects it has never seen; client baseline correctness is essential. The server may additionally retain known-ID tombstones. New observations after the baseline can be sent. If the adapter cannot safely establish the baseline, it leaves the dataset paused with an actionable status; fingerprints and reconciliation remain provisional until P0.

Legacy packets use a complete `baseline` followed by `snapshot` packets, each carrying the same `baseline_id` and a `native_epoch` UUID. The epoch identifies one verified continuous native counter lineage; generating an arbitrary UUID does not establish continuity. The server retains the source's epoch across resets and rejects a changed epoch. Untagged historical high-water with unknown lineage is only a conservative exclusion floor: it is merged componentwise with the new verified baseline without claiming historical lineage and can under-credit or pause future values until the floor is exceeded. Counter regression pauses ingestion. Legacy native adapter continuity remains unverified; the device must leave capture pending when it cannot establish that evidence. Generation-0 untagged writes remain supported; later new untagged writes are rejected, while exact retries and obsolete-generation handling remain intact. A baseline must fit the logical envelope limit and must never be truncated.

Reset removes live reading data, not every technical barrier. Packet/event identity hashes, annotation source ownership/body fingerprints, vocabulary fingerprints and cumulative raw legacy high-water counters may remain privately to prevent replay; old quote/note/context text is not retained in these barriers. For approximate legacy records, retain a raw high-water and the current reset baseline per source/date. Expose only componentwise `max(0, raw - baseline)` and merge those live values by max. A second reset advances the baseline to the cumulative raw high-water, not the previous live difference: raw100/reset, raw110/live10, reset, raw112/live2. Native counter resets may under-credit this approximate archive until the prior high-water is exceeded. These counters never enter the primary character/native-time series; unseen offline objects still require the client baseline.

## Uploads and covers

Direct JSON is limited to 1,048,576 bytes; a logical envelope is at most 16,777,216 bytes. `POST /api/v1/uploads` accepts `manifest` with the envelope identities, generation, byte length, raw SHA-256 and chunk count, and returns `created`. `PUT /api/v1/uploads/{upload_id}/chunks/{index}` sends raw bytes, each nonempty and at most 1,048,576 bytes, indexed from zero. The manifest chunk count cannot exceed the byte length and must be sufficient to carry it. `POST /api/v1/uploads/{upload_id}/commit` assembles in order, verifies manifest, hash and envelope identity, decodes UTF-8 only after assembly, and atomically applies the original envelope. Repeated identical chunks and commits are safe; changed bytes or identity are 409. Expiration is seven days, at most two open uploads per device; expiry returns 410 and the client creates a new upload ID with the same saved bytes and seq. Partial uploads never change live data. A single envelope above the logical limit remains queued with an explicit error; do not truncate it.

`PUT /api/v1/sources/{source_id}/cover` accepts JPEG or WebP bytes, maximum 65,536 bytes. Its raw-body request requires `X-Device-Id` (the bound device UUID) and `X-Reset-Generation` (a nonnegative decimal safe integer) headers. The server checks bearer binding, requires the current generation and an already existing source in that generation, and never creates source metadata from a cover. An old or future generation returns 409 without writing; `GET /api/v1/owner/sources/{source_id}/cover` serves an available cover to the owner. A full book file is never uploaded. 413 indicates a size limit; 429 carries Retry-After. Retries are 5/15/60/300 seconds while active, honouring Retry-After. A 401 pauses pending credential correction; 400/403/409/413 retain the queue with an actionable error. No network retry wakes a device or enables Wi-Fi.

## Owner reads and actions

All routes are relative to `/api/v1/owner`. The following response and request names refer to `$defs` in `read-api.schema.json`. IDs are UUIDs except source SHA. Missing resources return 404. Lists accept `cursor`, `limit` (1–100, default 50), and `byte_budget` (1–262144, default 262144); responses contain `items` and nullable `next_cursor`. After parsing URL strings to typed values, validate list parameters against `list_query`, date bounds against `daily_query` or `summary_query`, and content parameters against `content_query`. The byte budget is measured on UTF-8 JSON response bytes; do not split an item. If one item cannot fit, return 413 rather than silently omit it. Cursors are opaque, bound to the query/filter and a stable sort key; invalid cursors return 400. Quote/note previews are at most 500 Unicode characters. For field `context`, the concatenated content stream is UTF-8 JSON conforming to the event `context` definition, retaining before, selection_pages and after boundaries; detail contains only context status and bounded metadata. Its context_reason is a preview of at most 500 Unicode characters. Detail context_captured_at is a display timestamp truncated to at most three fractional-second digits (24 ASCII characters); the exact original timestamp and complete reason remain available through the paged context stream. Content is delivered separately in chunks of at most 262144 UTF-8 bytes, split only at Unicode character boundaries, with the cursor bound to annotation version; version change returns 409 `content_changed` and requires restart.

## Reporting semantics

- Unavailable volume/time contributes an unknown-status marker on the segment's `occurred_at` reporting date, without inventing numeric credit. For each metric, measured records plus unknown markers are partial; only unknown records are unavailable/null; an elapsed day with no observations is available/zero. Future days are unavailable/null and do not enter totals, streaks, averages or records.
- All-time elapsed days begin at the earliest nonfuture history-event date or primary credit date, whichever is earlier, through today. No history means zero elapsed days. Explicit date ranges count inclusive days from `from` through `min(to,today)`, including zero days; future-only ranges have zero elapsed days. An average with zero elapsed days is null.
- `record_day` is the day with the largest positive measured character amount in the requested period, with an earlier-date tie break; it is null if no positive measured volume exists. `current_streak` is anchored on today or yesterday and uses positive primary characters or native seconds, excluding legacy/future data. It respects book scope but ignores period bounds, since it describes the current series rather than a period record.
- A restored device identity may have a null token hash. It cannot authenticate until the new owner generates a fresh token; rotation preserves its restored device UUID. Backups contain no credential hash or owner/session credentials.
- Match rejections are stored by source and target book. Candidate reads suppress the corresponding mirrored pair through current memberships. A rejection follows the source and target while that target exists; it is not a permanent ban between every possible future regrouping.

Group and split preserve source IDs, notes, positions and immutable events. Split moves the selected nonempty proper subset of a book's sources into one new book; the remaining sources keep the original book ID. Selecting the entire group (including a singleton) returns 409 nothing_to_split. Merge removes emptied book groups; a later split creates a new book UUID rather than restoring an emptied group ID. Reversibility preserves source membership and source/annotation/event identities and data, not URLs of deleted book groups. An unset annual goal has target 0; it does not imply 100% completion. Book first_tracked_at and last_tracked_at are the minimum and maximum persisted history-event instants for member sources, or null when no history exists. active_days counts distinct primary reporting dates with positive measured characters on volume_date or positive allocated native seconds; it excludes legacy data and lifecycle/progress events without positive reading credit. A card uses the most recently opened source, not last network arrival. Current source progress uses the latest observed instant among its independently versioned progress snapshot and immutable progress samples; a snapshot wins an exact timestamp tie. Rejecting a match returns the source's unchanged current book; confirming returns the updated target book. Progress series remain per source. Completion is explicit; yearly goals count unique grouped books and rereading does not add a second unique book in the same year. Summary and day/session measurement statuses distinguish available, partial and unavailable: unavailable amounts are null, and partial amounts include only measured contributions. Summary volume and time sum sources without cross-format deduplication; native legacy is separate. Future dates do not penalize streaks or averages, which include elapsed zero days. No server response claims knowledge of the device's local queue unless explicitly sent as telemetry.
